# ECS アーキテクチャ基本設計書 (C++ Core / C# Application)

## 1. アーキテクチャ概要
本システムは、データ指向設計（DOD）に基づき、パフォーマンスと拡張性を最大化するEntity Component System（ECS）である。
コアロジックとメモリ管理をC++で行い、ゲームロジックおよびアプリケーション層の実装をC#で行うハイブリッド構成を採用する。

### 1.1 設計目標
* **キャッシュの最適化:** メモリの連続配置によるCPUキャッシュヒット率の極大化。
* **ポインタの安定性:** Chunked Storageを採用し、C#側でポインタを保持しても安全な設計。
* **高速な構造変更:** 毎フレームの大量のエンティティ生成・破棄、$O(1)$でのコンポーネント着脱。
* **シームレスな言語間連携:** C++/C#間の相互運用（Interop）コストの実質的ゼロ化。

---

## 2. コア・データ構造

### 2.1 EcsWorld (ワールド)
ECSの完全に独立したメモリ空間（レジストリ）の単位。
* **隔離性:** 複数シーンの同時実行を実現するため、シーンごとに独立したインスタンスを持つ。
* **ストレージ管理:** `TypeID` を用いた配列インデックスアクセスにより、ハッシュマップ検索を排除した $O(1)$ のストレージ取得を実現。

### 2.2 Entity (エンティティ)
データを持たない純粋な識別子（ID）。再利用時の安全性を担保するため、Generational Indexを採用する。
* **構造 (64-bit):**
  * `Index (32-bit)`: 配列へのアクセスに使用する一意の番号。
  * `Generation (32-bit)`: エンティティが破棄・再利用されるたびに加算される世代番号。ABA問題を防ぐ。

### 2.3 Component Storage (Chunked Sparse Set)
コンポーネント型ごとに、**Chunked Storage** と **Paged Sparse Array** を組み合わせたストレージを保持する。
* **Dense Array (Chunked Storage):**
  * コンポーネントの実データを 1024 要素ごとの固定長ブロック（チャンク）で管理する。
  * **アドレス固定化:** `std::vector<std::unique_ptr<T[]>>` で保持することで、要素増に伴う再確保が発生しても、既存の要素のメモリアドレスが変化しない。これにより、C#側で `Span<T>` を介して直接・安全にアクセス可能。
* **Sparse Array (Paged Sparse Array):**
  * EntityのIndexをキーとして、Dense Arrayのどこにデータがあるかを指し示す。
  * 4096要素（1ページ）単位で動的にメモリを確保し、メモリ爆発を防ぎつつ $O(1)$ アクセスを実現。
* **Swap and Pop:**
  * コンポーネント削除時は、該当チャンク内の「最後尾のデータ」を「削除対象の位置」に移動し、末尾を削ることで $O(1)$ 削除を維持する。

## 3. 高度なコンポーネント設計

### 3.1 Singleton Component (シングルトン・コンポーネント)
World内に1つしか存在しないデータを扱う。
* **実装:** 予約済みのID 0番エンティティ（`SINGLETON_INDEX`）に格納する。
* **安全性:** `get_or_add_singleton<T>` により、初回アクセス時に自動生成される。

### 3.2 Tag Component (タグ・コンポーネント)
データを持たない構造体。
* **実装:** `std::is_empty_v<T>` を用いてコンパイル時に判定。現在は管理の統一のため、1要素あたり1バイト（char）の最小メモリを確保する構成としている。

## 4. システムと実行制御

### 4.1 遅延構造変更 (Command Buffer)
* **仕組み:** ループ中のエンティティ操作（生成・破棄・着脱）は即時実行せず、`std::deque<std::function<void()>>` にキューイングする。
* **適用:** システム実行完了後、`submit_commands()` を呼び出すことで一斉に反映される。

### 4.2 クエリシステム (View)
* **機能:** 複数のコンポーネントを同時に持つエンティティを高速に抽出する。
* **最適化:** 検索対象の中で「最も要素数が少ないストレージ」をイテレーションのベースにする。
* **高度なフィルタリング:** `Exclude<T>` による「特定のコンポーネントを持たない」条件の指定が可能。

---

## 5. C++/C# 相互運用 (Data Binding)

### 5.1 Chunk-based Binding
1. C++はチャンクごとの先頭ポインタ（`get_chunk_ptr(index)`）とチャンク数を提供する。
2. C#側は各チャンクを `Span<T>` としてラップし、イテレーションを行う。
3. **アライメント・ガード:** 構造体のサイズをC++から取得し、C#側で不一致がないか実行時に検証する。

## 6. 今後の課題と懸念事項

### 6.1 コマンドバッファの最適化
* **懸念:** `std::function` によるアロケーション。
* **対策:** コマンドをシリアライズしてフラットなバイト配列に詰め込む「Ring Buffer型コマンドバッファ」の導入。

### 6.2 複合クエリのキャッシング
* **懸念:** 毎フレームの View 構築と最小ストレージの検索コスト。
* **対策:** クエリ結果（エンティティリスト）をキャッシュし、構造変更時のみ更新する仕組み。

### 6.3 言語間での定義自動同期
* **懸念:** C++とC#での構造体二重定義の保守コスト。
* **対策:** C++のヘッダーからC#の構造体定義を自動生成するツールの導入。

### 6.4 マルチスレッド化
* **懸念:** 現在の `EcsWorld` はスレッドセーフではない。
* **対策:** Job System との連携、およびコンポーネントの読み書き権限に基づくシステム並列実行エンジンの実装。
